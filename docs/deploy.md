# Deploy — Render + Neon

How the v1 web app goes live (plan M5). The repo side is `render.yaml`; the
steps below are the owner's, because they need accounts and secrets.

## Pieces

| piece | where | from |
|---|---|---|
| API + run worker | Render web service `orb-lab-api` (Starter, Singapore, always on) | `node api/server.js`; migrates and seeds on boot |
| Frontend | Render static site `orb-lab-web` | `web/` built to `web/dist`, every path rewritten to `index.html` |
| Database | Neon Postgres | pooled connection string |
| Fyers | a **second** Fyers API app, used only by the web callback | myapi.fyers.in |

## 1. Neon

1. Create a project (region: AWS Singapore, closest to Render's).
2. Copy the **pooled** connection string (host contains `-pooler`, ends with
   `sslmode=require`). It becomes `DATABASE_URL`.

## 2. Render blueprint

1. Render → New → Blueprint → this repo. Render reads `render.yaml` and creates
   both services.
2. It asks for every `sync: false` value. Fill what you have; the two URLs are
   known only after the first deploy, so put placeholders and fix them in step 4:

| variable | service | value |
|---|---|---|
| `DATABASE_URL` | api | Neon pooled string |
| `APP_PASSWORD_HASH` | api | `npm run -s hash-password` locally, paste the output |
| `FYERS_APP_ID`, `FYERS_SECRET_ID` | api | from the second Fyers app (step 3) |
| `FYERS_REDIRECT_URI` | api | `https://<api host>/auth/fyers/callback` |
| `FRONTEND_URL` | api | `https://<static site host>` (no trailing slash) |
| `VITE_API_URL` | web | `https://<api host>` (no trailing slash) |

`SESSION_SECRET` and `TOKEN_ENC_KEY` are generated by Render; `REST_DAILY_CAP`
is preset to 3800.

## 3. Second Fyers app

Create a new app on myapi.fyers.in with redirect URL exactly
`https://<api host>/auth/fyers/callback`. Keep the CLI's app as it is
(`http://127.0.0.1:5000/callback`), and set `REST_DAILY_CAP=1000` in your local
`.env`, so the two sides never exceed the account's 5,000 data calls a day.

## 4. Fix the URLs and redeploy

Once both services have their `onrender.com` hosts, set `FYERS_REDIRECT_URI`,
`FRONTEND_URL` and `VITE_API_URL` to the real values. `VITE_API_URL` is baked
in at build time, so redeploy the static site after changing it.

## 5. Check

- `https://<api host>/api/health` → `{"ok":true}`.
- Open the static site → sign in → Connect Fyers → header shows your name.
- Then the production smoke test (#40).

## Local production check

What #38 verified before any of this exists:

```bash
npm ci --omit=dev                                   # what Render's build runs
NODE_ENV=production PORT=4100 DATABASE_URL=… FRONTEND_URL=http://localhost:4173 \
  APP_PASSWORD_HASH=… SESSION_SECRET=… TOKEN_ENC_KEY=… FYERS_APP_ID=… \
  FYERS_SECRET_ID=… FYERS_REDIRECT_URI=http://127.0.0.1:4100/auth/fyers/callback \
  node api/server.js
cd web && npm ci && VITE_API_URL=http://127.0.0.1:4100 npm run build && npx vite preview --port 4173
```
